[STEP 1: 현황 진단 및 정리 설계]

1. 전체 분류 (A-G)

A. 런타임 필수 (Runtime Essential)
   - app/main.py (FastAPI Entrypoint)
   - app/core/* (Config, GCP Clients)
   - app/common/* (Schemas, Enums)
   - app/routers/ (auth.py, ingest.py, rag_search.py 등)
   - app/services/ (ingestion_service.py, drive_service.py 등 핵심 서비스)

B. 기능 모듈 (Feature Modules)
   - app/services/rag/ (RAG 파이프라인 SSOT)
   - app/services/sync_service.py

C. RAG 파이프라인 (RAG Components)
   - app/services/rag/orchestrator.py (Orchestrator)
   - app/services/rag/runner.py (Cloud Run Job CLI)
   - app/services/rag/steps/* (개별 단계 로직)
   - app/services/rag/retriever.py, generator.py, firestore_repo.py

D. dev/test 스크립트
   - scripts/test_rag_pipeline.py
   - scripts/dev/* (simulate_webhook.py 등)

E. 레거시 (Archive Candidate)
   - app/services/legacy/ai_a/ (구 RAG 시스템 전체 사본)
   - app/services/legacy/analysis_service.py (구 분석 서비스)
   - app/services/ai_b/ (사용 여부 확인 필요, 잠정 레거시)

F. 운영/보조 (Ops/Docs)
   - Dockerfile, .dockerignore, requirements.txt
   - DEPLOY_CLOUDRUN.md, README_STRUCTURE.md, REFACTORING_REPORT.md
   - static/

G. 시크릿 (Secrets)
   - .env (gitignore)
   - service_account.json (gitignore)

---

2. 중복 탐지 리포트

(1) 파일명 중복 (Basename Duplication)
   - `orchestrator.py` (SSOT) vs `pipeline_orchestrator.py` (Legacy/ai_a)
   - `steps/run_docai_extract.py` (SSOT) vs `legacy/ai_a/run_docai_extract.py`
   - `schemas.py`, `enums.py` : `app/common/` (SSOT) vs `legacy/ai_a/rag/app/common/common/`

(2) Import 의존성 분석
   - `app/main.py` -> `app.routers.rag_search` (앱 라우터 사용 중)
   - `app/routers/ingest.py` -> `app.services.rag.orchestrator` (앱 오케스트레이터 사용 중)
   - `scripts/test_rag_pipeline.py` -> `app.services.rag.orchestrator` (테스트 스크립트 사용 중)
   - **결론**: `app/services/rag` 경로가 실제 동작 코드이며, `legacy` 하위 코드는 런타임에서 분리됨.

---

3. SSOT 결정 (Design Decision)

- **RAG Core**: `app/services/rag/`를 유일한 정본으로 확정.
- **Common Module**: `app/common/`을 유일한 정본으로 확정.
- **Routers**: `app/routers/`로 평탄화 유지.
- **Legacy Policy**: `app/services/legacy/`는 삭제하지 않고 보존하되 `__init__.py` 등을 제거하여 오동작 방지 (Import 불가 처리). `app/services/ai_b`도 legacy로 이동 권장.

---

4. 산출물 및 실행 계획

(a) 정리 대상 (To-Be Actions)
   - MOVE: `app/services/ai_b` -> `app/services/legacy/ai_b`
   - KEEP: `app/services/rag` 및 `app/routers` 전체
   - UPDATE: `app/services/legacy` 폴더 내 Python 패키지 속성 제거 (Import 방지)

(b) 최종 목표 폴더 트리 (Services 부분)
   app/services/
   ├── rag/ (Active)
   ├── ingestion_service.py
   ├── drive_service.py
   ├── ...
   └── legacy/ (Archived)
       ├── ai_a/
       ├── ai_b/
       └── analysis_service.py

(c) 위험 요소
   - Cloud Run 환경변수 누락 (DEPLOY_CLOUDRUN.md 숙지 필요)
   - `simulate_webhook.py` 등 로컬 스크립트의 import 경로가 아직 깨져있을 수 있음.
